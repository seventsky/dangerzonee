    Sobre mim02

    eu sou só uma escritora. e se código também pudesse virar poesia?

    em resumo

    base
    Rio de Janeiro
    foco
    segurança da informação
    também
    desenvolvimento web e escrita
    leitura
    3 min
    ver projetos → falar comigo

    vim de uma família pobre, de uma comunidade no rio de janeiro. conheci a internet ainda nova, numa lan house em cima de uma loja de material de construção. lá eu "hackeava" jogo e rede social pros meus parentes sem fazer ideia do que aquilo significava.

    antes do código veio a arte. sempre gostei de poesia, de construir coisas com palavras, com desenho, com formas que mostravam como eu via o mundo. não deu certo.

    caí no subemprego porque era o que tinha. tentar uma segunda faculdade era luxo, eu não tinha tempo pra isso. "ser rico é ter tempo, e tempo é dinheiro, e é por dinheiro que a gente se mata."

    quando a vida melhorou, voltei a estudar, agora pensando no que dava pra fazer com o que eu gostava. comecei por html, css e javascript, sem saber direito nem a diferença entre estrutura, estilo e lógica. depois veio python e um pouco de java.

    só fazer site não bastava. eu queria saber o que rolava por trás, como um servidor responde, como os arquivos conversam entre si, o que acontece quando alguma coisa quebra. aí a segurança da informação entrou de vez. linux, redes, segurança web, ctf, red team, monitoramento. eu sempre gostei de investigar, e isso juntava tudo que eu passei a vida tentando entender.

    as três linguagens da web só fizeram sentido de verdade quando eu comecei meus próprios projetos e precisei fazer elas funcionarem juntas. o html é a estrutura, o css é a cara e o javascript é o comportamento.

    aprendendo no erro

    ler, ver tutorial e copiar é uma coisa. fazer o seu próprio projeto é outra, porque é aí que os problemas aparecem. um arquivo que existe e a aplicação não acha. um botão que aparece na tela e não funciona porque o js não carregou. um css que não pega porque o caminho tá errado. servidor local, localhost, porta. foi assim que eu aprendi a investigar a estrutura do projeto em vez de ficar encarando o código da tela.

    quase tudo eu aprendi no meu próprio computador. ele deixou de ser só a máquina onde eu estudo e virou meu laboratório. é nele que eu programo, uso linux, rodo servidor, mexo com git e wine, configuro serviço, leio log e testo aplicação. quando a parte gráfica dele quebrou, eu fui obrigada a entender pedaços do sistema que provavelmente só ia estudar muito depois. contei essa história aqui.

    o caminho ficou bem maior do que eu imaginava quando comecei.
